# crux v0.1.0

Test runner output is loud. A 200-test suite with 3 failures prints
hundreds of lines of pass/fail status, ANSI escape codes, and stack
traces stuffed with `node_modules` frames. Agents parsing that
output spend tokens on noise. Humans skim past it.

`crux` wraps your test runner and emits a compact failures-only
summary. One summary line, one block per failure, file:line, the
matcher diff. Exit code matches the runner's, unchanged.

## Install

```bash
npm install -g crux-cli
crux                            # auto-detect, summarize
crux --json                     # machine-readable
crux -- npx vitest run path/    # explicit command
```

Or without a global install: `npx crux-cli`.

## What's in v0.1.0

- `crux` CLI: auto-detects vitest in JS/TS projects. Markdown
  failures-only output by default. Flags: `--json`, `--raw`,
  `--cwd`, `--help`, `--version`, `--full`.
- `crux-mcp` MCP server (stdio, `@modelcontextprotocol/sdk`). One
  tool, `run_tests`, returning the same JSON envelope as
  `crux --json`.
- vitest adapter (default reporter): per-failure file:line:column,
  matcher diff (expected vs received), closest non-`node_modules`
  frame as `topFrame`. Compile-error, config-error, and
  binary-not-found classifications.
- Auto-detect from `package.json#devDependencies`, `vitest.config.*`,
  or `vitest.workspace.*`. Wrapper-script resolution for `npm test`,
  `pnpm test`, `yarn test`, `npm run <script>`.
- Passthrough mode for unknown runners or unparseable output.

## Numbers

Measured against `claude-opus-4-7` via Anthropic's `count_tokens`
API (ANSI-stripped) across 7 real OSS projects (22 to 4,456 tests,
including hono, vue core, and nuxt) plus 3 controlled failure
fixtures: **78% to 99.9% token reduction** (median ~89%). On the
hono run, crux is **662 tokens** vs `vitest --reporter=json` at
1.39M (more than 2,100x). Methodology and full table in
[`docs/report-v0.1.md`](docs/report-v0.1.md).

## Schema

`crux --json` and the MCP `run_tests` tool both emit a
`cruxVersion: 1` envelope. The schema is locked across v0.1 to
v1.x; field additions are additive, removals and type changes are
major-version-only.

## Use with agents

- Shell-using agents (Aider, Codex, anything reading `AGENTS.md`):
  copy [`docs/AGENTS.md`](docs/AGENTS.md) to your project root.
- Claude Code: copy
  [`docs/skills/crux/`](docs/skills/crux/SKILL.md) to
  `.claude/skills/` (or `~/.claude/skills/` for global use).
- MCP-using agents (Claude Desktop, Cursor, Cline): one-time host
  registration of `crux-mcp`. See
  [`docs/mcp-hosts.md`](docs/mcp-hosts.md).

## Constraints

- Node 20+.
- Two binaries (`crux`, `crux-mcp`), single package, single version.
- No telemetry. crux makes no network calls at runtime.
- No file-based config. Flags and environment variables only.
